# 健康方案规划与进度记录

## 数据文件(存放路径要求,必须遵守)

所有方案和历史记录**只能**存放在固定路径 `~/.health-plan/` 下。该路径独立于任何 agent 工具(Cursor、Claude Code 等),无论从哪个工具触发本 skill,都读写同一份数据,保证历史记录连续完整。Windows 上 `~` 即 `C:\Users\<用户名>`;文件一律 UTF-8 编码读写。

- `~/.health-plan/plan.md` — 当前生效的健康方案(改版时更新版本号,不另建新文件)
- `~/.health-plan/progress.md` — 进度日志,按日期倒序追加(最新在最上面)

规则:

1. 目录不存在时先创建(macOS/Linux:`mkdir -p ~/.health-plan`;Windows PowerShell:`New-Item -ItemType Directory -Force ~/.health-plan`)。
2. 禁止把方案或进度写到其他位置(skill 自身目录、项目目录、临时文件等)。
3. progress.md 只追加、不删改历史条目;修正错误时新增一条更正记录。
4. 用户询问历史记录、执行率、数据趋势时,一律以 `~/.health-plan/progress.md` 为准。

## 工作流程

**每次触发本 skill,先读取 `~/.health-plan/plan.md` 和 `~/.health-plan/progress.md`(如存在),再决定走哪个分支:**

**没有方案(plan.md 不存在)?** → 走「制定新方案」
**已有方案,用户来打卡/汇报情况?** → 走「记录进度」
**已有方案,用户问今天做什么?** → 根据 plan.md 的每周安排和今天星期几,列出当日任务
**到达复盘检查点或执行率明显偏低?** → 走「复盘调整」

### 制定新方案

1. 收集信息,缺少关键信息时用提问工具询问:
   - 基本情况:年龄段、身高体重、日常活动量
   - 目标:减脂 / 增肌 / 改善体能 / 缓解疲劳 / 改善睡眠
   - 约束:每周可用时间、可用场地、饮食偏好或忌口、已知伤病
2. 按下方「方案模板」制定方案,展示给用户,并写入 `~/.health-plan/plan.md`(文件头部记录制定日期和第几版)。
3. 在 `~/.health-plan/progress.md` 写入第一条记录,注明方案启动。

### 记录进度

1. 将用户汇报的内容整理成一条日志,追加到 `~/.health-plan/progress.md` 顶部,格式见「进度日志模板」。
2. 对照 plan.md 给出简短反馈:完成了什么、执行率如何、明天做什么。
3. 用户提供的量化数据(体重、精力评分、静息心率等)务必记入日志,便于复盘对比。

### 复盘调整

1. 统计 progress.md 中该周期的执行率和指标变化,对照 plan.md 的检查点逐项核对。
2. 执行率低于 60% → 简化方案;完成良好 → 增量不超过 10%。
3. 修改 plan.md(版本号 +1,保留修改日期),并在 progress.md 记录一条复盘结论。

## 制定原则

- **循序渐进**:从当前水平的 80% 起步,每周增量不超过 10%,避免受伤和放弃。
- **可执行优先**:方案要匹配用户的真实时间和场地,宁可简单能坚持,不要完美做不到。
- **量化目标**:用 SMART 原则,如"每周 3 次、每次 30 分钟快走"而非"多运动"。
- **针对久坐人群**(软件工程师常见):默认加入每小时起身活动、肩颈/腰背拉伸、护眼提醒。
- **安全边界**:如用户提到慢性病、伤痛、孕期等情况,提醒先咨询医生,不给出医疗建议。

## 方案模板(plan.md)

```markdown
# 个人健康方案(v1,制定于 YYYY-MM-DD)

## 用户画像
[目标、可用时间、场地条件、身体状况的一句话摘要]

## 目标
[1~3 条量化目标,含时间期限]

## 每周运动安排
| 时间 | 内容 | 时长 | 强度 |
|------|------|------|------|
| 周一 | ... | ... | ... |

## 饮食建议
- 三餐结构与大致热量/蛋白质目标
- 具体的加分项与减分项

## 睡眠与恢复
- 目标入睡/起床时间、睡前习惯建议

## 日常微习惯
- 每小时起身 2 分钟、拉伸动作等

## 复盘检查点(第 X 周,约 YYYY-MM-DD)
- [ ] 指标 1(如体重、静息心率、主观精力评分)
- [ ] 指标 2
```

## 进度日志模板(progress.md)

```markdown
## YYYY-MM-DD(周X)
- 完成:[当日完成的锻炼/习惯]
- 未完成:[计划内未做的项目及原因]
- 数据:[体重/精力评分/静息心率等,没有则省略]
- 备注:[用户主观感受或特殊情况]
```

## 示例

用户输入:"今天走了 40 分钟,做了拉伸,精力评分 6 分。"

处理:在 progress.md 顶部追加当日记录 → 反馈"周六任务全部完成,本周执行率 100%,明天周日休息" → 如有数据变化趋势,顺带提一句。
