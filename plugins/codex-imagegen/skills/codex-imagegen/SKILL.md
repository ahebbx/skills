# 图片生成与当前 Codex API 复用

把用户的图片需求完成为可预览、可下载的图片，而不是只给提示词。遵守用户当前授权；本技能不自动授权付费 API 调用。

## 选择执行方式

- 可用时优先使用内置图片生成工具，并遵守当前环境 imagegen 技能。
- 用户明确要求或已同意使用 API（例如“你当前的配置就可以”）时，复用现有配置，不重复要求用户提供密钥或重新确认同一操作。
- 内置工具不可用且用户尚未同意 API 时，说明替代方式及 API 费用，取得同意后继续。不要用 SVG、HTML 或代码绘图冒充用户要求的 AI 位图。

## API 配置发现

不要仅凭环境变量中没有 `OPENAI_API_KEY` 就断言用户没配密钥。先运行附带脚本的 `--check`，它只显示配置是否就绪，不输出密钥。

脚本读取 `CODEX_HOME`（缺省 `~/.codex`）下的 `config.toml` 与 `auth.json`，尊重选中的 profile、model_provider、provider.env_key、内联 token 和 requires_openai_auth。认证由 ChatGPT/OAuth 管理时，不尝试提取 OAuth token 充当图片 API key。已有聊天连接并不保证供应商支持图片模型或图片接口。

API 地址保留配置中的路径；只有完全不含路径的服务根地址才补 `/v1`。不向另一个域名试发当前凭据，不随意替换供应商。密钥只在内存及子进程环境中使用；禁止输出配置原文、打印密钥、把密钥写入提示词、命令行参数、日志或提交文件。

## 生成

1. 明确用途、比例、核心文案与风格。信息足够时直接采用合理设计，不为可调整的细节阻塞。商品主图可默认方形；黑灰绿是本次案例风格，不是所有图片的固定配色。
2. 将完整提示词保存为 UTF-8 文件。使用用途、构图、视觉主体、逐字文案、约束等字段。中文尽量精简并要求准确；不编造价格、服务范围、时效、官方身份或免费承诺。可参考 [商品主图案例](references/product-image.md)。
3. 定位当前 imagegen 技能的 `scripts/image_gen.py` 并阅读其 CLI 文档。附带脚本只负责安全传递当前配置，实际生成仍使用该工具。缺省查找 `$CODEX_HOME/skills/.system/imagegen/scripts/image_gen.py`；不同安装位置通过 `--cli` 指定。工具不存在时明确说明，不能假装已生成。
4. 使用支持 Python 3.11+ 的运行时及 `openai` SDK；在桌面环境可用 `load_workspace_dependencies` 查找 Python。缺依赖时安装到项目虚拟环境或工作目录，避免修改全局环境。网络受限时遵守环境的审批机制。

```bash
python /path/to/this-skill/scripts/generate_with_codex.py --check
python /path/to/this-skill/scripts/generate_with_codex.py \
  --prompt-file work/product-prompt.txt \
  --out outputs/product-main.png \
  --size 1024x1024 --quality high
```

默认使用 `gpt-image-2`，不把配置中的聊天模型当图片模型。尺寸和透明背景等能力以当前 imagegen 文档及供应商实际支持为准。不要静默切换到其他图片模型；必要时说明失败原因并征得用户对替代模型的同意。

认证失败、接口不存在或模型不支持时停止重复调用，汇报实际原因。网络瞬时故障可有限重试；超时不等于未计费，不要无限重试。轮询运行中的任务，每约一分钟提供有信息量的进展；不要启动重复生成任务。

## 检查与交付

打开实际输出检查：主题、文字、布局、裁切、水印以及用户约束。中文有错时围绕该问题修正，保存为新版本；不覆盖用户已有文件。所有成果写到当前任务规定的交付目录，临时提示词和依赖写到工作目录。不要把这次商品图片复制进技能仓库作为固定成果。

最终回复直接展示图片，并提供实际文件的绝对路径下载链接，简述风格、适用用途及实际使用的内置/API 方式。保存并链接完整提示词，便于后续复用。只报告真正生成成功的文件；不把生成请求已发出说成图片已完成。
